## TL;DR

`base` is a Claude Code companion. It installs a binary, registers **six global hooks** in `~/.claude/settings.json`
and **writes a section into `~/.claude/CLAUDE.md`**, then injects context into every Claude Code session on the
machine, in every repository.

1. **It updates itself by default, and the update is not verified.** Every session start can fetch upstream's latest
   release and swap the binary; no checksum or signature is checked, and the new binary is run (`--version`) before
   the swap. Off: `[update] auto = false`, or `BASE_NO_AUTO_UPDATE` (2.4).
2. **It writes global agent instructions without asking**, refreshed on every new version (1.3, 8).
3. **Its hooks put themselves back** after removal, once per version (3.2).
4. **It writes into every repository a session touches**: `.base-ast/` and two git hooks. No setting turns this off
   (5.3).
5. **It keeps full prompt text for 90 days by default**, after a scrub. Less: `[log] prompt_text = "matched"` or
   `"off"` (4.1).
6. **The opt-in dashboard listens on every interface with no authentication** and has write routes (4.4).
7. **The relay has no network listener**; it is file-based, and it is a cross-workspace channel (4.3).
8. **Nothing in the source sends data out with a POST.** Every HTTP call is a GET (4.2).
9. **A clean read is not a guarantee** ([last section](#a-clean-read-is-not-a-guarantee)).

### 1.6 Uninstall (`install.rs:213-291`)

- **FACT:** removes the hook entries, the `## BASE CLI` section and the corrections line, the binary, and the bundled

- **FACT** `remove_hooks` (`install.rs:293-336`): drops **any entry whose `hooks` list contains a command containing

- **FACT:** uninstall deletes with `remove_file` and `remove_dir_all`; nothing is moved aside first.

## 2. Updates

### 2.1 Trigger and frequency

- **FACT** `session_start.rs:184-186`: every SessionStart hook calls `auto_update(config)` and then
  `check_and_banner(out)`.
- **FACT** `session_start.rs:1057-1067`: `auto_update` returns early if `config.update.auto` is false, if the
  variable `BASE_NO_AUTO_UPDATE` is set (any value), or if `config.devmode.enabled`. Otherwise it calls
  `spawn_background_update()`.
- **FACT** `config.rs:1031-1045`: `[update] auto` **defaults to `true`**, and a config with no `[update]` section also
  updates (test at `config.rs:2032`).
- **FACT** `update/mod.rs:477-524`: the only throttle is the marker `~/.base-gbl/.update-inflight`. A new updater is
  not started while that marker is under 600 s old (484). **So every session start, outside that 10-minute window,
  sends one GET to `https://api.github.com/repos/ChristopherKahler/base/releases/latest`** (34-35, 139-178). The
  detached child runs `base update` with `BASE_UPDATE_BACKGROUND=1` and all output discarded (523).
- **FACT, a second check** `session_start.rs:1069-1108` and `manifest.rs:383-413`: a weekly check (TTL 604800 s,
  `manifest.rs:64-66`) GETs the same GitHub endpoint and `https://registry.npmjs.org/<pkg>/latest` for
  `paul-framework`, `@chrisai/seed` and `@chrisai/skillsmith` (`manifest.rs:305-309`). The npm lookups happen only for
  components registered in the manifest, which `base install --full` does. **This check is not gated by
  `update.auto`.** It only shows a banner (`manifest.rs:416-426`).

### 2.2 What it fetches and replaces (`run_quiet`, `update/mod.rs:585-610`)

1. It GETs the latest release JSON, takes `tag_name` and this platform's `browser_download_url` (139-178), and
   compares versions numerically (62-78).
2. It downloads the asset (256 MB cap, 180 s timeout; 40-45, 181-200) into `$TMPDIR/base-update-<pid>`.
3. It unpacks with the system `tar` (207-230).
4. **It runs the downloaded binary with `--version`** (364-374, called at 596). Unverified code runs before any
   decision is made.
5. It swaps the binary in place by rename (`atomic_swap`, 392-424) to `auto_install_dest()`, which is the running
   binary's own path (572-582).
6. **It copies the whole `scripts/` tree from the release** over `~/.base-gbl/scripts/` (263-318). That is Python the
   hooks later execute.
7. **It refreshes the `base-help` skill** in `~/.claude/skills/` from the GitHub contents API, silently (340-361,
   605). The fetch falls back from the tag to `main` (`install.rs:1584`).
8. The next session start, now on the new binary, adds any new hooks to `settings.json` (`session_start.rs:83`),
   rewrites the `## BASE CLI` section of `~/.claude/CLAUDE.md` (115-131), and starts a background store "upgrade"
   (`hook/mod.rs:232`, `upgrade/mod.rs:269-288`; see 5.2).
9. The result is logged to `~/.base-gbl/update.log` (460-475).

### 2.3 Integrity

- **FACT** `update/mod.rs:24-27`: *"There is no signature check and no checksum check in the download path, so the
  constant is the only thing vouching for what gets installed."* The API host is a hard-coded constant (34-35).
- **FACT** `update/mod.rs:94-98, 147-150`: if `GITHUB_TOKEN` or `GH_TOKEN` is in the environment, it is sent as
  `Authorization: Bearer` **to api.github.com only**. The asset download (185-189) sends no token.
- **FACT:** the updater is essentially unchanged since `566c7531` (30 lines of diff, mostly the wording of the notice
  and a switch to `detached::spawn`).

### 2.4 Ways to turn it off or pin a version

| Control | Where | Effect | Caveat (FACT unless marked) |
|---|---|---|---|
| `[update] auto = false` | `~/.base-gbl/base.toml` (`base config set update.auto false`) | Stops the background swap | **A workspace's `.base/base.toml` overrides it.** Scalars in the overlay replace the global value (`config.rs:1930-1931`), so a repository that ships `.base/base.toml` with `auto = true` switches it back on there. **A global `base.toml` that fails to parse loses the pin** (test `config.rs:2466-2493`: "the pin is genuinely lost") |
| `BASE_NO_AUTO_UPDATE=<anything>` | Environment of the hook process | Stops the background swap whatever the config says (`session_start.rs:1063`) | **INFERENCE:** it has to reach the hook processes, for example through the `env` block in `~/.claude/settings.json` |
| `[devmode] enabled = true` | `base.toml` | Also stops it (1063) | Adds a "MANDATORY: Append a DEVMODE block at the end of EVERY response" instruction (`user_prompt_submit.rs:1648`), and the upgrader may turn devmode off (`upgrade/mod.rs` lines 14-15) |
| `base update --snooze` | manifest | Hides the weekly banner for 24 h | The check itself still runs |
| `BASE_VERSION=vX.Y.Z` | `install.sh` only | Pins the first download | **No setting pins the version the updater installs.** It always installs upstream `latest` |

- **What it means:** forking alone does not insulate a user. `LATEST_RELEASE_API` points at upstream, so a fork-built
  binary is replaced by upstream's next release unless updates are off as above. Patching the fork (the constant at
  `update/mod.rs:34-35`, the default at `config.rs:1037-1039`) is the durable fix.

### 3.1 What is registered, and where

| Event | Command | New since `566c7531`? |

| PostToolUse | `base hook post-tool-use` | no |
| Stop | `base hook stop` | no |
| SessionEnd | `base hook session-end` | **yes** (v0.15.2's table had 5 entries) |

- **FACT** `install.rs:927-931`: each entry is `{"hooks":[{"type":"command","command":…}]}`, with **no `matcher`**
  (PreToolUse and PostToolUse fire on every tool) and **no `timeout`**.
- **FACT:** they are written to **`~/.claude/settings.json` only**, the user scope that applies to every project

- **FACT** `install.rs:1077-1121`: entries are inserted as text (`settings_json::add_hook_entries`), the file is backed
  up first, and an entry already present anywhere as a substring is never added twice (1094). **Changed since
  v0.15.2**, which parsed and rewrote the whole file.
- **INFERENCE:** the commands are resolved through `PATH`, so whichever `base` comes first on `PATH` when Claude Code
  runs the hook is the one that runs.

### 3.2 Hooks re-register themselves

- **FACT** `install.rs:1023-1061` (`ensure_hooks_wired`): adds any missing hook and writes the stamp
  `~/.base-gbl/.hooks-wired-<version>-<table hash>`. It runs at every SessionStart (`session_start.rs:83`) **and at
  the start of every `base` command** except `hook`, `install` and `uninstall` (`cli.rs:2154-2199`).
- **FACT:** `--skip-hooks` (`install.rs:79-84`) is not remembered anywhere (`git grep skip_hooks` finds only the flag
  itself).
- **INFERENCE (high confidence):** after `base install --skip-hooks`, the first ordinary command, such as
  `base doctor` or `base ast query`, finds no stamp and adds all six hooks. A hook removed by hand stays removed only
  until the version changes, and auto-update changes it.

### 3.4 Can it change what a session is allowed to do?

- **FACT:** no `permissionDecision`, `"permissions"`, allow or deny rules, `bypassPermissions` or `--dangerously…`
  anywhere in `src/` (`git grep`). Install writes only `hooks` into `settings.json`.
- **FACT, one way to block** (`pre_tool_use.rs:41-48`, `hook/memory.rs:202-213`): exit 2 blocks a Write or Edit to
  `~/.claude/projects/*/memory/*.md` (and to `MEMORY.md`, line 103: *"MEMORY.md is managed by BASE"*). This happens
  only when `[memory] enabled = true` and `mode = "base"`, and it is **off by default** (`config.rs:1157-1175`).
  **INFERENCE:** a repository that ships `.base/base.toml` can turn it on for sessions started in it (overlay,
  `config.rs:1930`). That would block Claude Code's own auto-memory in those sessions.
- **FACT, the skill widens permissions** `claude/skills/base-help/SKILL.md:5`:
  `allowed-tools: 'Read, Write, Edit, Bash(grep *), Bash(rg *), …, Bash(ls ~/.base-gbl/*)'`. While the skill runs,
  unrestricted `Write` and `Edit` are pre-approved.
- **FACT** `llm.rs:244-247`: the vision helper runs `claude -p … --allowedTools Read` (only from
  `base graph extract --multimodal`). `measure.rs:495` uses `--permission-mode dontAsk --allowedTools "Bash(echo measure)"`
  (only `base doctor --measure`). `tune_pass.rs:90-92` runs Haiku with no settings, no MCP and no tools.

### 3.5 Living beside other PreToolUse hooks

- **FACT:** base's PreToolUse has no matcher and fires on every tool call. Its output is a JSON `additionalContext`
  envelope (`hook/mod.rs:265-275`). Nothing in it coordinates with another tool's hook; its de-duplication is per
  session and per repository, for its own hints only (`ast_hint.rs:19-22`).
- **FACT:** base's global CLAUDE.md text says *"ALWAYS use `base ast query` BEFORE grep, find, Read, or any MCP tool"*
  (`install.rs:1739-1741`), and its search hint redirects grep, rg, find and fd to `base ast query`
  (`ast_hint.rs:9-17`).
- **INFERENCE (from how Claude Code works, not from this repository):** hooks that match the same event run in
  parallel with no guaranteed order, and each one's `additionalContext` reaches the model unmerged. A user who already
  runs another code-graph tool with its own search hint should expect two competing "query my graph first"
  instructions, one of them backed by a global "MANDATORY" line, and two code maps per repository.
