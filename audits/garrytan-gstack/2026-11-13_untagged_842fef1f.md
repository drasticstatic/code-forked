## Thank you

gstack is the work of Garry Tan and its contributors. Thank you for building it and sharing it under MIT. The source
documents its own defaults and trade-offs unusually well: every setting has a default and a comment, outbound calls
carry receipts, and the sandbox escape hatch warns every time it is used. What follows describes the code at one
revision, so that anyone can decide to run it on purpose. It is not a judgement of the authors.

## TL;DR

The broadest of the projects reviewed in this round: an installer (`setup`), dozens of skills, helper binaries, Claude
Code hooks, an updater, telemetry, an outside-model review path and a local browser daemon.

1. **Setup writes hooks into the user-level `~/.claude/settings.json`.** By default that means **one Stop hook**
   (timeline repair, local only), which then runs on every Stop event in every repository. Team mode adds a
   SessionStart updater hook. Two more hooks are offered behind a prompt that defaults to no (new in this read; 1.2).
2. **Defaults:** telemetry `off`, `auto_upgrade` `false`, `update_check` `true`, outside reviews `enabled` (2).
3. **Outside reviews send repository content to another model** (Codex or Claude Code) under the user's own CLI
   login, unless `codex_reviews` is set to `disabled` (2).
4. **Telemetry off is not network off.** The update check contacts GitHub by default (4).
5. **The Codex sandbox is `read-only` by default.** Full access only with `GSTACK_CODEX_NO_SANDBOX=1` in the shell, with
   a warning each time (7).
6. **The cookie importer decrypts real browser cookies**, through the system keychain or secret store (5).
7. **The browser daemon listens on loopback only.** A public tunnel needs two explicit opt-ins (6).
8. **Some agent instructions arrive at run time** from a helper's output, not from the skill text (1.3).

## 1. Setup

### 1.1 Hosts, Bun and dependencies (finding 1)

- **FACT** `setup:24`: `--host <name>     Install for one host. Default: claude.` Lines 24-49 list the optional hosts,
  `--team`, `--no-browser` and `--no-harness-auto`.
- **FACT** `setup:327-332`: an older Bun is refused, because *"older Bun ignores --no-compile-autoload-dotenv, so
  gstack's compiled tools could read a project's .env."*
- **FACT** `setup:1912-1924`: for a user install, `bun install --production --frozen-lockfile`, and if the lock is out
  of date, `bun install --lockfile-only` (dependencies resolved again) and then a frozen install (`:1916`, `:1923`).
  For a contributor install, or when dev dependencies are present, the fallback is a plain `bun install` (`:1920`).
- **What it means:** the lock file is used when it matches. When it does not, the installed versions come from the
  registry on the day.

### 1.2 Hooks written to `~/.claude/settings.json` (not in the first read's edition)

| Hook | Event | Default | Turn it off | Source |
|---|---|---|---|---|
| Timeline repair | `Stop`, no matcher | **on** | `--no-timeline-stop-hook`, `GSTACK_TIMELINE_STOP_HOOK=no`, `timeline_stop_hook: no`, or `--no-team` | `setup:4886-4926`; `bin/gstack-config:353` `timeline_stop_hook) echo "yes"` |
| Session updater | `SessionStart` | team mode only | `--no-team` | `setup:4432-4442` |
| Plan-tune capture and preference | `PostToolUse` and `PreToolUse` on `AskUserQuestion` | **asked**: `[y/N]`, defaults to no after 10 s, skipped without a terminal | `--no-plan-tune-hooks` | `setup:4621-4829` |
| AskUserQuestion error fallback | `PostToolUse` on `AskUserQuestion` | installed with the plan-tune hooks | as above | `setup:4750-4764` |
| Skill routing / skill contracts | `UserPromptSubmit` / `Stop` | **off** | n/a | `lib/skill-route.ts:40-45` |

- **FACT** `hosts/claude/hooks/timeline-stop-hook.ts:1-40`: the default Stop hook appends "completed" entries to the
  project's gstack timeline. It always exits 0 and, in its own words, *"runs on EVERY Stop event machine-wide"*
  (`:19`). No network call was found in it.
- **FACT** `setup:4813-4815`: the plan-tune PreToolUse hook uses Claude Code's `permissionDecision` to enforce
  "never-ask" preferences.
- **FACT** `setup:4825`: a `settings.json.bak.<ts>` backup is written before any change.
- **FACT** `setup:4309-4313`: a setup run for a non-Claude host never touches Claude Code hooks.

### 1.3 Instructions that arrive at run time (not in the first read's edition)

- **FACT** `SKILL.md:34-41`: the root skill tells the agent to run `gstack-skill-start` and to follow any
  `GSTACK_INSTRUCTION_BEGIN … GSTACK_INSTRUCTION_END` blocks in that command's output, but only when they come from
  that command and carry the session id it just printed.
- **INFERENCE:** some agent instructions (onboarding and consent steps) come from an executable's output, so what they
  say depends on the installed version, not on the skill text read here.
- **FACT** `SKILL.md:129`: the telemetry step is marked *"PLAN MODE EXCEPTION — ALWAYS RUN"*. It writes locally under
  the gstack state root.

## 2. Defaults and outside reviews (finding 2)

- **FACT** `bin/gstack-config:328-357` (the defaults table): `telemetry` `off` (332), `auto_upgrade` `false` (333),
  `update_check` `true` (334), `codex_reviews` `enabled` (340), `plan_tune_hooks` `prompt` (352),
  `timeline_stop_hook` `yes` (353).
- **FACT** `bin/gstack-config:221-223`: *"Outside review (Codex or Claude Code by harness): sends the review prompt
  and repository content to that model. enabled (default; the first send prints a notice once)"*.
- **FACT** `lib/outside-consent.ts:52-54`: a review the user asks for by name is always allowed. Otherwise `enabled`
  **or unset** is allowed, and only `disabled` refuses (`bin/gstack-outside-voice:98-105`, `not_run
  consent_missing`).
- **Off:** `gstack-config set codex_reviews disabled`.
- The notice-once behaviour is taken from the config comment; its code was not traced.

## 3. Updates (finding 3)

- **FACT** `bin/gstack-session-update:214-217`: exits unless `auto_upgrade` is `true`. `:438-448`: `git fetch` of the
  `stable` or `main` channel. `:577`: then `./setup -q --refresh-registered`.
- **FACT** `setup:4433`: team mode sets `auto_upgrade true` itself.
- **FACT** `bin/gstack-upgrade:77`: preflight. `:83-84`: refuses a detached HEAD ("a pinned revision"). `:87`: refuses
  a branch other than the remote default.
- **What it means:** a solo install does not upgrade itself. A team install follows a moving branch and re-runs setup,
  which can register hooks again (1.2).

## 4. Network by default (finding 4)

- **FACT** `bin/gstack-update-check:85-88`: `raw.githubusercontent.com/garrytan/gstack/<channel>/VERSION` and the
  GitHub compare API. `:68`: `curl -sf --max-time 5`. **Off:** `update_check: false`.
- **FACT** `bin/gstack-telemetry-sync:50`: exits when the tier is `off`. `:92-94`: removes `_repo_slug`, `_branch` and
  `repo` (and `installation_id` for `anonymous`) before upload.
- **FACT** `supabase/config.sh:8` holds a Supabase anonymous client key (the value is not reproduced here; such keys
  are meant to be shipped to clients).

## 5. Browser cookies (finding 5)

- **FACT** `browse/src/cookie-import-browser.ts:2`: *"read and decrypt cookies from real browsers"*. `:17` macOS
  Keychain, `:19` Linux libsecret, `:20` Windows DPAPI.
- **INFERENCE:** on macOS, reading the browser's Keychain entry raises a system prompt. Imported session cookies work
  as logins.

## 6. Browser daemon (finding 6)

- **FACT** `browse/src/server.ts:1969` and `:422`: both listeners bind `127.0.0.1`. `:315-325`: the extension-token
  route requires the pinned extension origin and a loopback Host. `:120`: a missing or short `AUTH_TOKEN` falls back
  to a random UUID.
- **FACT** `:2123-2124`: `BROWSE_TUNNEL=1` is ignored unless `pair_agent` is on. `:334-360`: the ngrok token is read
  from `NGROK_AUTHTOKEN`, `~/.gstack/ngrok.env`, or ngrok's own config files.

## 7. Sandboxes and permission flags (finding 7)

- **FACT** `bin/gstack-codex-probe:226-237`: *"Every gstack Codex command passes -s / sandbox_mode from this
  variable"*. It is `read-only`, unless `GSTACK_CODEX_NO_SANDBOX=1` comes from the shell environment (*"never a dotenv
  file or config"*). Then it is `danger-full-access`, with a warning on every use.
- **FACT** `:446`: the model probe runs `codex exec … -s read-only`.
- **FACT:** among the 63 top-level `SKILL.md` files, the only mention of full access is `codex/SKILL.md:603`, which
  describes that opt-in.
- **Where the readings differ:** the first reviewer lists "danger-full-access workflow skills/helpers" among the bypass
  mentions. In the files the second reviewer read, full access is an opt-in that warns, not a default. Nested skill
  files, tests and evaluation code were not searched, so both readings stand.
