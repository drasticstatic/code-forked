## Thank you

Open Second Brain is the work of its contributors, shared under the MIT licence. Thank you for building it and
publishing it. The source explains its own boundaries in unusual detail: the egress guard says what it redacts and what
it deliberately does not, the trust helper says it is so far pinned only by fixtures, and opt-in hooks say so in their
status lines. What follows describes the code at one revision so anyone can choose how to run it; it is not a judgement
of the authors.

## TL;DR

1. **Installing the Claude Code plugin registers 27 hook commands on 9 events** and two MCP servers, one always loaded
   (1.1, 1.2). The install page mentions one of those hooks.
2. **Lifecycle capture runs whenever a vault or brain store is configured**; there is no single off switch for it, but
   session and message exclusions in `_brain.yaml` apply first. Recall injection and handoff notes are off by default
   (2.1).
3. **Deferred capture spools to the system temp folder** with owner-only permissions (2.2).
4. **Exports pass one guard** that redacts tokens and URL credentials and leaves out prompt-derived pages unless asked
   (2.3).
5. **The `prepare` script sets `core.hooksPath`** in the git checkout it runs in (1.3).
6. **A clean read is not a guarantee** ([last section](#a-clean-read-is-not-a-guarantee)).

## 1. Install surface

### 1.1 Hooks (`hooks/hooks.json`)

- **FACT:** 27 hook commands on nine events: `PostToolUse` (line 3), `SessionStart` (43), `UserPromptSubmit` (86),
  `PreToolUse` (123), `Stop` (147), `SubagentStart` (178), `SubagentStop` (191), `SessionEnd` (204), `PostCompact`
  (223). Each runs `$CLAUDE_PLUGIN_ROOT/scripts/o2b-hook <name>` or an `o2b-hook` on `PATH`, with a 10 s timeout, and
  exits 0 if neither is found.
- **FACT:** status messages mark some hooks *"(opt-in)"*, for example recall-inject (`:98`), the navmap tier, the
  counterparty brief, the gap agenda, host-settings backup (`:142`). Session capture, active-inject, the post-write
  reminder, subagent-inject, view-render, the stop-log guardrail and the quote check carry no such label.
- **FACT** `install/claudecode.md:60-63`, *"Lifecycle hooks (auto-enabled)"*, names only the `PostToolUse` hook on
  `Write|Edit|MultiEdit|apply_patch`.
- **FACT** `hooks/pretool-host-backup.ts:3-6, 24-26`: the PreToolUse backup of `.claude/settings*.json` is opt-in
  (`host_settings_backup`, default OFF) and, when on, denies a write it cannot back up first.

### 1.2 MCP servers

- **FACT** `.claude-plugin/plugin.json:12-21`: two servers, `open-second-brain` and `open-second-brain-writer`
  (`"alwaysLoad": true`), both running `${CLAUDE_PLUGIN_ROOT}/scripts/o2b mcp`. `install/claudecode.md:3-6`: they are
  registered by the plugin, with no `claude mcp add` step.
- **FACT** `install/claudecode.md:33-36`: `o2b init` stores `vault`, `agent_name` and `timezone` in
  `~/.config/open-second-brain/config.yaml`; the servers read it at start.

### 1.3 `prepare`

- **FACT** `package.json:61`: `"prepare": "bun scripts/prepare.ts || exit 0"`.
- **FACT** `scripts/prepare.ts:19-22`: if `git rev-parse --git-dir` succeeds, it runs
  `git config core.hooksPath .githooks`.
- **INFERENCE:** it applies to whichever repository encloses the working directory. In a development clone that is the
  project itself; run inside a folder that sits in another repository, it would change that repository's setting.
  Installing the plugin through Claude Code's marketplace does not run it.

## 2. Data

### 2.1 What is captured, and the switches

- **FACT** `src/core/config.ts:844-851`: boolean switches are on only for `"true"` or `"1"`.
- **FACT** `config.ts:1069-1073`: handoff notes *"Default OFF"*. `:1386-1398`: prompt-time recall injection
  *"Default OFF"*. `:1661-1668`: recall dedupe *"Default ON"*.
- **FACT** `hooks/session-capture.ts:237-250`: the capture hook returns early only when no vault or brain store
  resolves; otherwise it captures. It is registered on SessionStart, UserPromptSubmit, Stop, SubagentStop, SessionEnd,
  PostCompact and one PostToolUse matcher.
- **FACT** `src/core/brain/capture-boundary.ts:4-21`: one boundary decides what may become evidence; session and message
  patterns can ignore or suppress; *"Everything fails soft to 'capture'"*, except that settings which exist but cannot
  be read make it capture nothing.
- **Where the readings differ:** none on the flags. The second reviewer adds that the lifecycle capture path has no
  enable flag of its own at this revision.

### 2.2 Deferred capture

- **FACT** `hooks/session-capture.ts:9-25`: events that need the dedup index go to a detached worker;
  `OPEN_SECOND_BRAIN_SESSION_CAPTURE_DEFER=0` turns the hand-off off.
- **FACT** `session-capture.ts:95-97`: the spool is `tmpdir()/o2b-capture-<pid>-<random>.json`, `mode: 0o600`; the
  worker deletes it after reading (`:194-202`).

### 2.3 Exports

- **FACT** `src/core/egress/guard.ts:2`: *"The one call every export path makes before its bytes leave the vault."*
  `:36`: *"`redactTokens` is ON."* `:43-48`: `redactInfra` is off; only URL credentials are taken, so host names and IPs
  in notes are kept. `:193`: prompt-derived content is excluded by default; `--include-prompt-derived` includes it.
- **FACT** `src/core/path-safety.ts:27, 48-53` and `src/core/derived-store-guard.ts:9-10, 67-70`: paths are checked
  lexically and through `realpath`; derived files are read with `O_NOFOLLOW`. Races between check and use were not
  reviewed.
