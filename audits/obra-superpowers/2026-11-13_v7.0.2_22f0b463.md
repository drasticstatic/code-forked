## TL;DR

A plugin of process skills (brainstorming, TDD, debugging, planning and more) with one hook.

1. **One SessionStart hook, on by default with the plugin.** At startup, `/clear` and compaction it injects the whole
   `using-superpowers` skill into the session. It only reads that one local file: no network, no file writes, no
   settings writes (1).
2. **The injected skill puts skills first.** It tells the agent to invoke a skill at even "a 1% chance" of relevance,
   before any reply or clarifying question. That is a workflow priority over the user's own conventions, not a
   permissions change (2).
3. **Permission-bypass flags appear only in the test scripts**, never in the hook, the skills or the manifests (3).
4. **MIT** (4).

### 1. The SessionStart hook

- **FACT** `hooks/hooks.json:3-12`: one `SessionStart` entry, `"matcher": "startup|clear|compact"`, running
  `"${CLAUDE_PLUGIN_ROOT}/hooks/run-hook.cmd" session-start` with `"async": false`.
- **FACT** `hooks/session-start:25-32`: reads `skills/using-superpowers/SKILL.md` with the bash `read` builtin.
  `:49` wraps it as *"<EXTREMELY_IMPORTANT>\nYou have superpowers. … Below is the full content of your
  'superpowers:using-superpowers' skill"*. `:76-88` prints the envelope each host expects.
- **FACT:** the script makes no network call, writes no file and touches no settings. `run-hook.cmd` only finds
  `bash` and `exec`s the named script (`:79`).
- **INFERENCE:** it applies to every session wherever the plugin is enabled. Installed at user scope, that is every
  repository.

### 2. The entry skill

- **FACT** `skills/using-superpowers/SKILL.md:11`: *"If you think there is even a 1% chance a skill might apply to what
  you are doing, you ABSOLUTELY MUST invoke the skill."* `:13`: *"IF A SKILL APPLIES TO YOUR TASK, YOU DO NOT HAVE A
  CHOICE. YOU MUST USE IT."*
- **FACT** `:20`: invoke skills *"BEFORE any response or action — including clarifying questions"*. `:22`: brainstorm
  before entering plan mode. `:6-8`: a dispatched subagent is told to ignore the skill.
- **What it means:** the text ranks this plugin's skills ahead of other conventions in the session. It asks for
  nothing outside the skill system: no fetching, no settings changes, no installs.

### 3. Permission bypass

- **FACT:** `--dangerously-skip-permissions` appears only in `tests/explicit-skill-requests/*.sh` (for example
  `run-test.sh:73`). `--permission-mode` appears in
  `tests/claude-code/test-subagent-driven-development-integration.sh:167`. Neither appears in `hooks/`, `skills/`, the
  plugin manifests or `.opencode/`.

### 4. Licence

- **FACT** `LICENSE:1` *"MIT License"*; `.claude-plugin/plugin.json:11` `"license": "MIT"`.
