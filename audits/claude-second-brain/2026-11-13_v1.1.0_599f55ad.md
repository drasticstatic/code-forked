## Thank you

claude-second-brain is the work of its author (GitHub: jessepinkman9900). Thank you for building it and sharing it.
The installer explains itself as it goes: it says why the 2 GB model download is skipped, it creates GitHub
repositories as private, removal asks with "no" as the default answer and keeps remotes unless told otherwise, and
the vault's instructions keep raw sources apart from the wiki written from them. What follows describes what the code
does at one revision, so that anyone can decide to run it on purpose; it is not a judgement of the author.

## TL;DR

`csb` (run with `npx claude-second-brain`) scaffolds a vault under `~/.claude-second-brain/<name>`, installs tools,
installs three global Claude Code skills, commits the vault, and can create and push a remote.

1. **Interactive setup defaults to a private GitHub repository and pushes to it**; the non-interactive default is no
   remote (1.2).
2. **Three skills are written to `~/.claude/skills/`**, the user scope every Claude Code session loads. A same-named
   skill folder that the installer did not write is overwritten without a prompt; `CSB_SKIP_SKILL_UPDATES=1` installs
   rather than skips (1.3).
3. **It installs mise globally with npm if missing, runs `mise trust`, and installs node, pnpm and the vault's
   dependencies**, resolved on the day (1.1, 5).
4. **The vault ships with the Obsidian Git community plugin enabled and set to commit and push every five minutes**,
   once Obsidian loads it (2).
5. **The search index is not git-ignored, although the vault's instructions say it is,** so it is in the first commit
   and push (3).
6. **The optional Cloudflare route prints tokens to the terminal** in two places (4).
7. **MIT licence;** the bundled Obsidian Git code carries its own notices, including one LGPL-3.0-or-later notice (6).

### 1.2 The remote

- **FACT** lines 1040-1054: `remoteProvider` starts as `"none"`; interactively the choice is GitHub (the default,
  1051), Cloudflare Artifacts or skip.
- **FACT** lines 1181-1206: for GitHub, runs `gh auth login` if not logged in (1188-1191), then
  `gh repo create <name> --private --source=. --remote=origin --push` (1196).
- **What it means:** with the defaults, the initial commit (everything in the vault, see 3) goes to a new private
  GitHub repository.

### 1.3 Global skills

- **FACT** line 302: `brain-ingest`, `brain-search`, `brain-refresh`, written to `~/.claude/skills/<name>/SKILL.md`
  with a `.csb-version` file (389-398).
- **FACT** lines 319-323: a skill folder with no `.csb-version` counts as not installed and is written **without a
  prompt**, in every mode. **INFERENCE:** a user's own skill of the same name is replaced.
- **FACT** lines 333-337: when versions differ and the run is non-interactive, **or when `CSB_SKIP_SKILL_UPDATES=1`**,
  every skill is updated. The variable's name suggests the opposite.
- **FACT** lines 339-366: interactively it asks once, defaulting to "Update all" (346).
- **FACT** `template/.claude/skills/brain-ingest/SKILL.md:17, 23` (and `brain-refresh/SKILL.md:17-18, 56, 66`): the
  skills run `npx -y claude-second-brain …` each time. **INFERENCE:** each use runs whatever version npm serves that
  day, from every Claude Code session, since the skills are global.

### 1.4 Removal (`csb rm`)

- **FACT** lines 866-876: asks before deleting the vault folder and config entry, default **No** (870). Lines 878-905:
  asks per remote, default No. `-y` skips the first question and **keeps** remotes (886). `--delete-remote` deletes
  the GitHub repository (`gh repo delete --yes`, 276) or Cloudflare artifact with no prompt (880, 893). Line 919:
  `rm(target.path, { recursive: true, force: true })`.

## 2. The bundled Obsidian Git plugin

- **FACT** `template/.obsidian/community-plugins.json:2`: `"obsidian-git"` is enabled. `manifest.json:9`: version
  `2.38.0`. The plugin's code (`main.js`, 727 KB minified) is committed in the template.
- **FACT** `template/.obsidian/plugins/obsidian-git/data.json`: `autoSaveInterval: 5` (6), `autoPushInterval: 0` (7),
  `autoPullInterval: 5` (8), `autoPullOnBoot: true` (9), `autoCommitOnlyStaged: false` (10), `disablePush: false`
  (11), `pullBeforePush: true` (12), `autoBackupAfterFileChange: true` (22), `differentIntervalCommitAndPush: false`
  (26).
- **FACT** `main.js` line 219: when `differentIntervalCommitAndPush` is false, the auto-backup timer calls
  `commitAndSync`. Line 403: `commitAndSync` commits, pulls, and then pushes unless `disablePush`, when a remote is set
  and pushing is possible.
- **What it means:** `autoPushInterval: 0` does not stop pushes. With these settings, every five minutes after a
  change the vault is committed (all changes, not only staged ones) and pushed.
- **INFERENCE (Obsidian's behaviour, not this repository's):** Obsidian loads community plugins only after the user
  turns off Restricted mode for the vault. Until then the plugin does nothing.
- **FACT** `obsidian_askpass.sh:3-23`: writes git's credential prompt to the file named in
  `$OBSIDIAN_GIT_CREDENTIALS_INPUT`, waits for a `.response` file, prints its contents to git, then removes both. How
  the plugin creates those files (location, permissions) **could not be checked** in the minified bundle.

## 3. The search index and `.gitignore` (new in this read)

- **FACT** `template/.gitignore.template:2`: the ignore line is `qmd.sqlite*`.
- **FACT** `template/scripts/qmd/setup.ts:18-22` and `bin/create.js:1038`: the index is `.qmd/index.sqlite` inside the
  vault. The pattern above does not match that file.
- **FACT** `template/CLAUDE.md:215`: the index is *"stored at `.qmd/index.sqlite` (gitignored, relative to vault
  root)."*
- **FACT** `bin/create.js:1143-1145`: `qmd:setup`, which creates the index, runs **before** `git add .` and the first
  commit (1171-1174) and the GitHub push (1196).
- **INFERENCE (not run):** the index is in the initial commit and push, and each later re-index is committed and
  pushed by the plugin settings in 2. What the index holds (text, embeddings, paths) is decided by qmd and was not
  checked.
- **FACT:** `raw-sources/` (including `raw-sources/personal/`) is not ignored. That is by design, since the vault is
  the repository; it means those files go wherever the vault is pushed.

## 4. Cloudflare Artifacts (opt-in) and tokens

- **FACT** `bin/create.js:98-105`: uses `CLOUDFLARE_API_TOKEN` if set, otherwise Wrangler's login (`wrangler whoami`,
  `wrangler auth token`, 108-165).
- **FACT** lines 168-172: if the token contains non-ASCII characters it is refused, and **its first 60 characters are
  printed** as a "token preview" (`truncate`, 90-93). **INFERENCE:** for a token of usual length, that is the whole
  token. Line 175 otherwise logs its length and first 8 characters.
- **FACT** lines 213-244: creates the artifact repository, adds the remote, and pushes with `git -c
  "http.extraHeader=Authorization: Bearer <repo token>"` (230). The token is not written to `.git/config`;
  **INFERENCE:** it is visible on the command line while git runs.
- **FACT** line 1218: prints the repository token in full, for the user to save.

## Questions worth answering before running it

1. Is a global install of three skills (and anything with the same name already there) acceptable, given they run
   `npx -y` from every session? (1.3)
2. Should the vault have a remote at all, and is Obsidian Git with these settings wanted? If not: choose "Skip" for
   the remote, and set `disablePush: true` or remove the plugin before opening the vault. (1.2, 2)
3. Add `.qmd/` to `.gitignore` before the first commit if the index should stay local. (3)
4. Is a global `npm install` of mise and `mise trust` acceptable on this machine? (1.1)
