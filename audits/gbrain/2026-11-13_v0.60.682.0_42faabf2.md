## Thank you

GBrain is Garry Tan's work, shared under the MIT licence. Thank you for building it and publishing it. The source is
unusually candid about its own limits: the self-updater says in plain words which parts of the signature chain it does
not check, the guardrails module says it only observes, and the setup help names every flag that changes what gets
written. What follows describes the code at one revision so that anyone can choose how to run it; it is not a judgement
of the author.

## TL;DR

1. **The install guide recommends the hosted service first**, through `curl … | bash` from a third-party host, then
   documents a keyless self-hosted path that skips capture, cron and paid enrichment (1.1).
2. **`gbrain setup claude-code` writes a "brain-first" block into `~/.claude/CLAUDE.md` by default**, plus
   SessionStart and UserPromptSubmit hooks at user scope (every Claude Code session). `--no-instructions` and
   `--no-hooks` turn these off; capture and paid providers are off unless asked for (1.2).
3. **The package's postinstall runs `gbrain apply-migrations --yes`** when a `gbrain` is already on `PATH` (1.3).
4. **Once the autopilot daemon runs, Git sync is on unless turned off**, and it pushes local commits by default for
   checkouts GBrain cloned itself and for managed worktrees; it never force-pushes and runs a secret scan first. The
   memory-only install does not set up autopilot (2.1).
5. **Self-update defaults to notify**; silent install is opt-in. Downloads are checked against a GitHub build
   attestation before they run, without independent Fulcio/Rekor validation, as the source itself says (2.2).
6. **A clean read is not a guarantee** ([last section](#a-clean-read-is-not-a-guarantee)).

## 2. Background behaviour

### 2.1 Git reconcile under autopilot

- **FACT** `src/commands/autopilot-daemon.ts:333-337`: each daemon tick runs `autopilotReconcile` unless
  `automaticGitPullDisabled`.
- **FACT** `src/core/persistence/automatic-sync-policy.ts:7-20`: `autopilot.git_pull` is *"default on"*; only an
  explicit non-truthy value turns it off.
- **FACT** `src/commands/sources-git-reconcile.ts:93` with `src/core/sync-policy.ts:21-27`: a source is skipped only
  when its config says `syncEnabled: false`; *"absent/undefined is NOT disabled."*
- **FACT** `sources-git-reconcile.ts:108`:
  `publish = optedOut.length ? false : group.managed ? publishSetting !== false : publishSetting ?? cloned`.
  So local commits are pushed by default for managed worktrees and for checkouts GBrain cloned itself; a user's own
  checkout is not pushed unless `sources.refresh_publish_diverged` is set true. `sources.auto_reconcile.source.<id>
  = false` turns publishing off for one source (`src/core/persistence/worktree-refresh.ts:483-487`).
- **FACT** `src/core/git/reconcile.ts:5-7, 136-139`: merges happen in memory, *"never a rebase or force-push"*; a
  rewritten upstream refuses; pushes run `gbrain git commit-push --push-only --scan-secrets --expect-remote`.
- **FACT** `INSTALL_FOR_AGENTS.md:631`: autopilot is *"Optional: skip this entire step for memory-only installs. Ask
  before scheduling."*
- **Where the readings differ:** the first reviewer read the gate as "requires `brainSyncConfig.enabled === true`" at
  `src/commands/autopilot-git-reconcile.ts:21-34` and saw fetch and push at lines 125-147 and 237-245. At this
  revision that file has 22 lines and no such symbol; the gate found is an opt-out. Both reviewers agree that the
  default memory-only install was not shown pushing anything.

### 2.2 Self-update

- **FACT** `src/core/self-upgrade.ts:6, 59, 767-784`: modes `auto | notify | off`; the default is `notify`; `auto` is
  opt-in. `autopilot-daemon.ts:320-322`: *"No-op unless mode=auto."*
- **FACT** `src/core/binary-self-update.ts:23-38`: the downloaded binary's SHA-256 is checked against the GitHub
  build-provenance attestation and the builder id before it is executed; *"it does NOT independently validate the

- The first reviewer cited lines 96-113 for this; the text is in the header comment at 23-38.
