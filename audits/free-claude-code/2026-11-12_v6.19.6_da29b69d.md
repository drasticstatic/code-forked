## Thank you

Free Claude Code is Ali Khokhar's work (GitHub: Alishahryar1). It is a large, carefully built project: the code is
well organised, the risky settings are named and commented, the Admin pages check where a request comes from, and
errors are scrubbed of key-shaped strings before they reach a client or a log. Thank you for building it and sharing
it. What follows describes what the code does at one revision, so that we can run it on purpose; it is not a
judgement of the author.

## TL;DR

1. **Started with its defaults, the proxy listens on every network interface with authentication off.** Any device
   that can reach the port can use the provider keys it holds. Four settings, set before the first start, change that
   ([below](#settings-we-pin-before-first-run)).
2. **The one-line installer and `fcc-update` run the newest upstream release, not the revision read here.** We do not
   use them.
3. **The messaging bots start Claude Code with permission checks turned off.** We do not enable them.
4. **Web search and web fetch are on by default** and run from the server itself.
5. **A clean read is not a guarantee** ([last section](#a-clean-read-is-not-a-guarantee)).

## What it does by default, and what is opt-in

### Installers and updater

**The one-line installer runs the latest release's installer, not the file you are reading** (default).
`scripts/install.sh` lines 1739-1756 ask GitHub for the latest release, download that tag's `install.sh` and run it:

```sh
selected_installer=$(curl -fsSL --max-time 10 --max-redirs 5 "https://raw.githubusercontent.com/Alishahryar1/free-claude-code/v$fcc_install_version/scripts/install.sh")
...
FCC_INSTALL_VERSION=$fcc_install_version _FCC_INSTALLER_RELEASE=$fcc_install_version exec sh -c "$selected_installer" sh "$@"
```

The only check on the download is a shell syntax check (`sh -n`, line 1751): no checksum, no signature. Reading
`scripts/install.sh` at a revision therefore does not show what will run on the day. The README's one-liner starts
from upstream `main` (`curl -fsSL ".../main/scripts/install.sh" | sh`).

**It installs from PyPI, not from a checkout** (default). Lines 1631-1658 run
`uv tool install --force --refresh-package free-claude-code` with the spec `free-claude-code[==<version>]`. *(inference)*
`uv tool install` resolves dependencies afresh against the lower bounds in `pyproject.toml` and does not use the
repository's `uv.lock`.

**Third-party installers.** The installer can download and run the install scripts of other coding agents (Claude
Code, Codex, Pi, OpenCode, Hermes, Grok, Muse, Antigravity, uv and others, lines 7-21; `download_and_run`, lines
539-611, checks only that the file is not empty). Each agent's flag defaults to on (lines 28-38). Asked interactively,
every prompt defaults to No (lines 211-236). **Run without a terminal** (a script, CI, a wrapper), there is no prompt
(lines 1844-1847) and every missing agent is installed. Their scripts were not reviewed (they are not in the
repository).

**Other installer effects** (default): `uv tool update-shell` (line 1662), which *(inference)* adds a PATH line to shell
start-up files; on macOS, the desktop app install (below). No `sudo`, no LaunchAgent and no login item were found in
the installer or the source. An optional RTK and Headroom step (`--rtk-headroom`, prompt defaults to No) patches
Claude Code's and Codex's global configuration (lines 782-846).

**`fcc-update`** (opt-in: only when typed). `scripts/update/fcc-update` lines 17-18:

```sh
installer=$(curl -fsSL "https://raw.githubusercontent.com/Alishahryar1/free-claude-code/v$release_version/scripts/install.sh")
FCC_INSTALL_VERSION=$release_version _FCC_INSTALLER_RELEASE=$release_version exec sh -c "$installer" sh "$@"
```

The version comes from `_fcc-update-check`, which follows GitHub's "latest release" redirect and checks PyPI
(`src/free_claude_code/updater/check.py` lines 11-12, 25-48). It always moves to the latest release and reruns the
whole installer. Nothing in the server, launchers or desktop app calls the updater: there is no background update
check.

**The uninstaller deletes `~/.fcc` without a backup** (opt-in: only when run). `scripts/uninstall.sh` line 272,
`run rm -rf "$fcc_home"`; that folder holds the keys, the database, the logs and sign-in state. `--dry-run` prints the
plan first.

### Launchers (`fcc-claude` and the others)

- **Each launcher sets the proxy address and token in the child's environment only** (`harnesses/environment.py`
  lines 10-35); nothing is exported to the parent shell. The token is `ANTHROPIC_AUTH_TOKEN`, default `freecc`.
- **`fcc-claude` removes every `ANTHROPIC_*` variable and `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC`** from the
  child, then sets its own, including `CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY=1` and `DISABLE_ERROR_REPORTING=1`
  but not `DISABLE_TELEMETRY` (`harnesses/claude.py` lines 11-48). Someone who sets the non-essential-traffic flag for
  privacy loses it inside a session started this way.
- **When no server is running, a launcher starts one, detached, and it keeps running** (default). On macOS and Windows
  the command it starts is the menu-bar app, not the plain server (`cli/launchers/common.py` line 108):

  ```python
  name = "fcc-desktop" if sys.platform in {"win32", "darwin"} else "fcc-server"
  ```

- **A browser tab opens on the Admin page when the server first starts** (default): `FCC_OPEN_BROWSER` defaults to
  `True` (`config/settings.py` line 736).
- No launcher writes `~/.claude/`, `~/.claude.json`, Claude Code's `settings.json`, hooks or shell profiles. Temporary
  configuration goes under `~/.fcc/tmp/launchers/` (folder 0700, files 0600) and is removed when the launch ends
  (`harnesses/resources.py` lines 13-42).

### The desktop app (macOS)

- **Installed as part of every macOS install** (default; `scripts/install.sh` lines 1687-1694). It creates
  `~/Applications/Free Claude Code.app`, signs it locally with `/usr/bin/codesign --force --sign -`
  (`cli/macos_app.py` lines 117-122), and puts a link to it on the Desktop (lines 139-146). It leaves anything at
  those paths that it did not create alone.
- **Its executable is a prebuilt binary that is not in git.** `pyproject.toml` ships
  `src/free_claude_code/assets/macos/fcc-desktop-*` from the wheel; the source of that launcher
  (`scripts/macos/launcher.m`, 105 lines) is compiled in release CI. The binary in the wheel was not compared with that
  source.
- It runs the same server inside the app, with a menu-bar icon (Open Admin, Check Server Status, Restart Server,
  Quit). It registers no login item. **It is not needed:** `fcc-server` runs the same server without it, and a
  launcher that finds a healthy server starts nothing (`cli/launchers/common.py` lines 280-284).

### Network defaults and authentication

**Default bind address and authentication** (`config/settings.py` lines 734-744):

```python
host: NonEmptyString = Field(default="0.0.0.0", validation_alias="HOST")
port: int = Field(default=8082, validation_alias="PORT")
open_admin_browser: bool = Field(default=True, validation_alias="FCC_OPEN_BROWSER")
proxy_auth_enabled: bool = Field(
    default=False,
    validation_alias="PROXY_AUTH_ENABLED",
)
proxy_auth_token: NonEmptyString = Field(
    default="freecc",
    validation_alias="ANTHROPIC_AUTH_TOKEN",
)
```

and the check every model route depends on (`api/dependencies.py` lines 52-53):

```python
    if not settings.proxy_auth_enabled:
        return
```

What that means with the defaults:

- **Any device on the same network can use the model routes** (`/v1/messages`, `/v1/chat/completions`,
  `/v1/responses`, `/v1beta/models/...`, `/v1/models`), billed to the provider keys the server holds, and can call
  `/stop`, which cancels running sessions. `/health` never asks for a token.
- **The addresses shown to people say `127.0.0.1`** even when the server listens on `0.0.0.0`
  (`config/server_urls.py` lines 12-13), so it can look local-only when it is not.
- **The default token is public.** With authentication on but the token left as `freecc`, anyone who has read the
  README knows it. Tokens are compared in constant time (`api/dependencies.py` lines 154-157).
- **The Admin pages and Admin API are local-only.** `require_loopback_admin` (`api/admin_security.py` lines 58-67)
  needs a loopback peer address, a loopback `Host` header and, if present, a loopback `Origin`; all 42 Admin route
  functions call it, and the code-session routes carry it as a router guard. There is **no Admin password**: any
  program on the same computer can read the masked settings, rewrite `~/.fcc/.env` (including `HOST` and
  authentication) and start code sessions.
- *(inference, not tested)* With authentication off, a web page open in a local browser may be able to reach the model
  routes on 127.0.0.1, since those routes check neither `Host` nor `Origin`. Authentication with a non-default token
  closes that path.
- FastAPI's built-in `/docs`, `/redoc` and `/openapi.json` pages are not turned off (`api/app.py` line 53) *(inference
  from FastAPI's defaults)*. They describe the API's shape, not its secrets.
- **Legacy settings are imported on first run.** If `~/.fcc/.env` does not exist, the settings in
  `~/free-claude-code/.env`, `~/.config/free-claude-code/.env`, a checkout's own `.env`, or `FCC_ENV_FILE` are copied
  into it (`config/paths.py` lines 79-86; `config/env_migrations.py` lines 191-262). If the imported file had a
  non-empty token, authentication is written as on; if it had none, as off (lines 464-480). The source files are left
  where they are, with their permissions unchanged.

### Logging

- **The log** is JSON lines at `~/.fcc/logs/server.log` (`config/paths.py` lines 95-98), at `INFO` by default
  (`config/settings.py` line 660). At `INFO` no request bodies, headers or keys were found in any log call the
  reviewers traced.
- **Rotation deletes older files.** `config/logging_config.py` lines 77-78:

  ```python
  rotation="50 MB",
  retention=5,
  ```

  Loguru keeps the five newest rotated files and deletes the rest.
- **`LOG_LEVEL=DEBUG` alone writes whole conversations.** `core/trace.py` lines 4-6: "Conversation and Claude Code
  prompts are logged verbatim unless values live under sanitized credential keys". That does not depend on
  `LOG_RAW_API_PAYLOADS`. Redaction is by key name only, so a key pasted into a prompt or a file is written as it is.
- **More detail, each off by default** (`config/settings.py` lines 662-683): `LOG_RAW_API_PAYLOADS` (whole request
  bodies, plus HTTP library debug output), `LOG_RAW_SSE_EVENTS` (streamed model output), `LOG_API_ERROR_TRACEBACKS`,
  `LOG_RAW_MESSAGING_CONTENT`, `LOG_RAW_CLI_DIAGNOSTICS`, `LOG_MESSAGING_ERROR_DETAILS`.
- `~/.fcc/logs/startup.log` is truncated each time a launcher starts the server (`cli/launchers/common.py` lines
  123-131).

### Where keys are kept

- **Provider keys and the proxy token** live in `~/.fcc/.env`, written atomically and set to mode 0600
  (`config/env_migrations.py` lines 317-344). *(inference)* The temporary file is chmod'ed after it is written, so for
  a moment it has the default mode.
- `~/.fcc` itself is set to 0700, and the database files to 0600, when the database first opens
  (`runtime/sqlite_database.py` lines 235-242). Connected-account tokens go to `~/.fcc/auth/` (0700 / 0600).
- **The Admin API never returns a key**: secret fields come back as `********`, and key lists as a revision hash and
  entry numbers (`config/admin/values.py` lines 57-130; `config/admin/credentials.py` lines 46-63).
- **The Admin "Connect" buttons write the proxy token in plain text into other programs' settings** (opt-in): for
  example `claudeCode.environmentVariables` in VS Code's user `settings.json`, `~/.codex/config.toml`, and Antigravity
  and Claude Desktop settings (`runtime/integration_service.py` lines 342-569). Once connected, these files are
  refreshed at every server start.

### Outbound traffic

- **No telemetry, analytics or crash reporting** was found (a search of the source, scripts and `pyproject.toml`).
- **Model providers** are called only when chosen as the model, a fallback or an override, or when the owner presses
  Test or Refresh in Admin. Each call carries the conversation and that provider's key (`config/provider_catalog.py`
  lines 11-105 list the default addresses). Mistral and OpenCode also receive a client session id, and OpenCode the client's User-Agent
  (`providers/mistral/caching.py` lines 34-60; `providers/opencode/provider.py` lines 152-175).
- **Web search and fetch, on by default** (`config/settings.py` lines 646-648, `ENABLE_WEB_SERVER_TOOLS=True`). When a
  model asks, the server sends the search query to `https://lite.duckduckgo.com/lite/`
  (`runtime/web_tools/client.py` line 157) and fetches the address the model chose, from the owner's own connection.
  Fetches to private and loopback addresses are refused unless `WEB_FETCH_ALLOW_PRIVATE_NETWORKS=true` (default
  `false`, lines 654-656; `runtime/web_tools/egress.py` lines 30-88).
- **Messaging bots** connect only when a bot token is set; `MESSAGING_PLATFORM` defaults to `discord` but does
  nothing without `DISCORD_BOT_TOKEN` (`config/settings.py` lines 368-370, 719-721).
- **The update check** contacts GitHub and PyPI, and only inside `_fcc-update-check`.

## Settings we pin before first run

Set in `~/.fcc/.env` (mode 0600) or in the process environment; a value in the process environment wins and locks the
Admin field (`config/admin/values.py` lines 65-68).

| Setting | Our value | Default | Why |
|---|---|---|---|
| `HOST` | `127.0.0.1` | `0.0.0.0` | listen on this computer only |
| `PORT` | `8082` | `8082` | written down so the wrappers agree |
| `PROXY_AUTH_ENABLED` | `true` | `false` | otherwise every model route is open |
| `ANTHROPIC_AUTH_TOKEN` | a long random value | `freecc` | the default is public |
| `FCC_OPEN_BROWSER` | `false` | `true` | no browser tab at every start |
| `LOG_LEVEL` | `INFO` | `INFO` | `DEBUG` writes whole conversations |
| `LOG_RAW_API_PAYLOADS`, `LOG_RAW_SSE_EVENTS`, `LOG_API_ERROR_TRACEBACKS`, `LOG_RAW_MESSAGING_CONTENT`, `LOG_RAW_CLI_DIAGNOSTICS`, `LOG_MESSAGING_ERROR_DETAILS` | `false` | `false` | written down so a later edit is visible |
| `WEB_FETCH_ALLOW_PRIVATE_NETWORKS` | `false` | `false` | keeps web fetch off the local network |
| `ENABLE_WEB_SERVER_TOOLS` | `false` | `true` | search queries and fetches would leave from our connection |
| `MESSAGING_PLATFORM` | `none` | `discord` | the bots are not used (next section); `none` is an accepted value (`config/settings.py` line 783) |

We also start the plain server ourselves, in a terminal, before any client, so that no launcher starts the desktop
app in the background.

## Parts we do not use, and why

| Part | Why |
|---|---|
| The one-line installer (`curl ... \| sh`) | it runs the latest release's installer, checked only for syntax, and installs from PyPI rather than from our reviewed fork |
| `fcc-update` | it always moves to the latest release, past the revision read here, and reruns the whole installer |

| The upstream launchers, for now | on macOS a launcher with no server running starts the desktop app and opens a browser; we start the server ourselves and point Claude Code at it |

## A clean read is not a guarantee

This review says what the source at `da29b69d` does, as far as two careful readers could tell in one day. It cannot
see what was not read (listed above), what runs but is not in the repository (packages fetched on the day, prebuilt
binaries, third-party installers), or a mistake the readers made. An antivirus scan of the same revision is a separate
step, and a clean scan would not be a review either. The reviewed revision is a starting point for running the tool
on purpose, with the settings above, not a promise about it.
