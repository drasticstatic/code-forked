## Thank you

COG is Huy Tieu's work (GitHub: huytieu). Thank you for building it and sharing it. The source is candid about its own
moving parts: the updater lists every file it will replace and offers check and dry-run modes, the onboarding skill
waits for the user to confirm what it captured, a vendored skill keeps its author's licence and a note on where it
came from, and the harvest skill says plainly that no hooks ship. What follows describes what the repository does at
one revision, so that anyone can decide to run it on purpose; it is not a judgement of the author.

## TL;DR

COG is a vault template plus a large set of agent instructions (a `CLAUDE.md`, 40-odd skills, worker agents and
roles), a shell updater, and optional Python, JavaScript and shell tools.

1. **The updater writes whatever upstream `main` holds,** over a fixed list of files that includes the updater itself,
   the scripts it then runs, and `.gitignore`. No tag, checksum or signature is checked. Pressing Enter at a prompt
   accepts, without a backup; `--force` accepts everything, with backups (1).
2. **Even `--check` and `--dry-run` add a git remote and fetch** before they decide anything (1.2).
3. **An always-apply rule tells the agent to keep a daily journal**, appending after meaningful work without
   announcing it. Saying "stop" stops it for the session (2.1).
4. **Personal folders are not git-ignored by default.** The exclusions are written but commented out, and an update
   that replaces `.gitignore` comments them out again (3).
5. **No code pushes, and no hooks ship.** One always-apply rule says "create new commits and push normally" (3, 5).
6. **Some optional tools reach out:** an ElevenLabs audio script (with the user's API key) and a browser screen
   recorder; personalised news research reads the user's profile and watchlist (4).
7. **MIT licence**, with a vendored skill under its own MIT notice (7).

## 1. The updater (`cog-update.sh`)

### 1.1 What it replaces, from where

- **FACT** `cog-update.sh:16-18`: remote `cog-upstream` = `https://github.com/huytieu/COG-second-brain.git`, branch
  `main`.
- **FACT** lines 23-275 (`FRAMEWORK_FILES`): docs, skills, agents, plugin metadata, and also **`cog-update.sh` itself**
  (33), `.claude/lib/checkpoint.sh` and `lane-classify.sh` (37-38), `scripts/validate-agent-surface.sh` (40),
  `scripts/build-agent-plugin.sh` (271) and **`.gitignore`** (274). Personal content folders are not in the list.
- **FACT** lines 356-362: each file is written with `git show "${REMOTE_NAME}/${BRANCH}:${file}" > "$file"`. Nothing
  checks a tag, checksum or signature.
- **FACT** lines 386-407, 529-530, 608-609: after updating, it runs `./scripts/build-agent-plugin.sh` and the
  validator, both of which it may just have replaced.
- **INFERENCE (not run):** bash reads a script as it goes. Rewriting `cog-update.sh` in place while it runs can make
  bash continue from the old byte position in the new file after `main` returns. Force mode exits first (531);
  interactive mode does not.

### 1.2 Modes and defaults

- **FACT** line 440: `ensure_remote` (318-325: `git remote add` if missing, then `git fetch cog-upstream main`) runs
  **before** the check (484) and dry-run (499) branches. Those two modes therefore change the repository's git
  configuration and fetch, though they change no files.
- **FACT** lines 538-551: interactive mode asks about each **new** file, `[Y/n]`, and Enter means yes.
- **FACT** lines 556-596: for each **changed** file it asks `[Y/n/d(iff)/b(ackup+update)]`. Enter, or any answer other
  than `n`, `d` or `b`, updates **without a backup** (592-596). Only `b` keeps a backup.
- **FACT** lines 516-531: `--force` updates every file in the list without asking, keeping
  `*.backup-YYYYmmdd-HHMMSS` copies (368, 520).
- **FACT** `.claude/skills/update-cog/SKILL.md:23-31`: the skill gives the agent the same add-remote and fetch steps;
  it applies when the user asks to update or check the version (14-16).

### 1.3 What it means

Running the updater, in any mode, trusts whoever controls upstream `main` on that day. Copying files from a reviewed
tag is the way to take a known revision.

## 2. Agent instructions that run by default

### 2.1 The daily journal

- **FACT** `CLAUDE.md:182-190`, headed *"Daily Journal (ALWAYS APPLY)"*: *"After finishing a meaningful unit of work,
  append one entry to `01-daily/journal/YYYY-MM-DD.md`"* (186); *"Do not announce the write — append and carry on"*
  (188); trivial reads and *"anything you asked to keep out"* are not logged (188); *"If you say to stop journaling,
  stop for the rest of the session"* (190).
- **What it means:** this is an instruction to the agent, not a background process. It runs whenever the agent follows
  `CLAUDE.md`, and the entries are written without being mentioned.

### 2.2 Onboarding

- **FACT** `.claude/skills/onboarding/SKILL.md:53-64`: extracts name, role, interests, news sources, projects and
  companies or people being tracked from what the user writes. Lines 80-99: shows what it captured and *"Wait for
  confirmation"* before creating files. Lines 128-146: records which integrations are active or disabled; *"Always add
  `ElevenLabs` to **Disabled** unless explicitly requested"* (146).

### 2.3 Other always-apply rules worth knowing

- **FACT** `CLAUDE.md:155`: *"Always create new commits and push normally."* (In context: never `reset --hard` or
  `--amend`.) Line 156: Conventional Commits.
- **FACT** `CLAUDE.md:199`: disabled integrations are skipped *"silently … do not mention them in output."*

## 3. What git would carry

- **FACT** `.gitignore:15-36`: *"Personal Content — NOT ignored by default"*. Ignore lines for `00-inbox/` to
  `06-templates/` are present but commented out, for users of the public repository to switch on.
- **FACT** `cog-update.sh:274`: `.gitignore` is a framework file, so an update that is accepted (or forced) replaces it
  with upstream's, with those lines commented out again.
- **FACT** `.gitignore:52`: `*.backup.* # created by cog-update.sh`. gitignore has no trailing comments, so the whole
  line is one pattern; the updater's backups are named `*.backup-<date>` (368). **INFERENCE:** the backups are not
  ignored, and the suggested `git add -A` (611) would commit them.
- **FACT:** no script in the files read pushes. **Two readings of `CLAUDE.md:155`:** the first reviewer found no
  default push in the reviewed core; the second reviewer agrees there is no push in code, and adds that an
  always-apply rule says "push normally", which an agent may treat as permission to push.

## Questions worth answering before using it

1. Take files from a reviewed tag, or run the updater against `main`? (1)
2. Is a silent, always-on journal wanted? It can be turned off for a session by saying so, or by removing the section
   from `CLAUDE.md`. (2.1)
3. Where will the vault be pushed, if anywhere, and have the personal-folder lines in `.gitignore` been switched on
   (and kept on after updates)? (3)
4. Does an existing `CLAUDE.md` already set rules for commits and pushing that COG's always-apply rules would compete
   with? (2.3)
