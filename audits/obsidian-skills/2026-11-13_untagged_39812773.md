## TL;DR

This repository is **instructions, not code**: seven Markdown skills, their references, manifests for three agent
hosts, and one maintainer script. Nothing in it runs by itself.

1. **No hooks, no MCP server, no background process, no pre-approved tools.** No manifest declares any, and no skill
   has an `allowed-tools` line (5.1).
2. **The CLI skill drives the running Obsidian app**, including deleting (to the trash), renaming, moving, and running
   JavaScript inside the app with `obsidian eval`. Its cautions are instructions to the agent, not limits on the tool
   (2.1).
3. **The Headless skill handles Obsidian Sync and Publish** with the user's own account. It tells the agent never to
   ask for the password, to dry-run before publishing, and to confirm before remote changes (2.2).
4. **The Defuddle and Knap skills may offer a global `npm install`** of an unpinned package; Defuddle fetches the page
   it is given (2.3).
5. **The Markdown, Bases and Canvas skills describe file formats** and create or edit files in the vault (2.4).
6. **Every documented install route follows the default branch**, not a revision. Copying the folder by hand is the
   only route that keeps exactly the text reviewed here (1).
7. **MIT licence.** It does not cover the external tools the skills call (6).

## 2. What each skill tells the agent to do

### 2.1 `obsidian-cli` (the running desktop app)

- **FACT** `obsidian-cli/SKILL.md:8, 12`: uses the `obsidian` command that ships with the app; Obsidian must be open,
  with the CLI turned on.
- **FACT** line 16: *"The CLI exits with status 0 even when a command fails, so read its output before reporting that
  a command succeeded."* Line 18: *"pass note text as literal argument data, never as executable shell syntax."*
- **FACT** lines 48, 55: without `file=`/`path=` the **active file** is used; without `vault=` the target is *"the
  vault that contains the current directory, then the most recently focused vault"*, and `vault=` *"only works as the
  first parameter; anywhere else it's ignored"*. Line 61: if the target is unclear, ask which vault before changing
  files.
- **FACT** lines 66-82: read, create, append, rename, move, delete, `property:set`, daily notes, tasks. Line 82:
  *"`delete` moves the file to the trash; don't pass `permanent` unless the user asks for it."* Line 38: use
  `overwrite` only when replacing a file is intended.
- **FACT** lines 99-119: plugin development: reload a plugin, read errors and console, take a screenshot, inspect the
  DOM. Lines 123-127: **`obsidian eval code="…"` runs JavaScript in the app.** Line 141: CDP and debugger controls
  exist (`obsidian help`).
- **What it means:** the cautions are good ones, and they are instructions to the agent. Whatever the agent is allowed
  to run in a shell, the CLI can do, including `eval`.

The first reviewer placed screenshots and DOM inspection at lines 123-141; at this commit they are at 109-119, and
123-141 hold `eval`, CSS inspection, mobile emulation and the CDP pointer. The finding is the same.

### 2.2 `obsidian-headless` (Sync and Publish without the app)

- **FACT** `obsidian-headless/SKILL.md:14`: if `ob` is missing, *"offer installation with `npm install -g

- **FACT** line 22: *"ask the user to run it in their own terminal. Don't ask for their password or pass it with

- **FACT** line 26: *"Before a command that changes remote state, confirm the vault, site, and path from list or status

- **FACT** lines 37, 44: `--continuous` keeps syncing until stopped (*"start it in the background or as a service"*).

### 5.2 Agent-directed text

82; Headless lines 22, 26, 30, 52, 70). The sample prompts in `plugins/obsidian/plugin.json:30-56` are examples of
what a user might ask.

## Questions worth answering before using it

1. Which install route? Copying `plugins/obsidian/skills/` from a known commit keeps the reviewed text; marketplace
   and `npx skills` installs follow `main`.
2. Which skills? The format skills (Markdown, Bases, Canvas) only shape files. The CLI skill controls the running app,
   including `eval`. The Headless skill uses Sync and Publish credentials and can publish. Each is a separate choice.
3. Are global `npm` installs of `defuddle`, `knap` or `obsidian-headless` wanted, and at which version?
4. Is the Maps community plugin acceptable? Only the Bases map view needs it.
